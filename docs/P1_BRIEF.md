# P1 实施简报（v0.1 范围内，不升级 v0.2）

依据：GPT 2026-10-23 P0 验收指令第五节。原则：复用现有环境与成熟模块、渐进式、每步可运行可验证。

## 目标

1. 语义证据整理、融合与充分性评价；
2. Working / Episodic / Long-term Memory 渐进式实现；
3. 保留跨任务元元认知的研究接口；
4. 不做长程任务 Agent，不做 RSI，不擅自升版本。

## P1-a：语义证据整理、融合与充分性评价（先做）

**技术路线**：复用已装的 transformers 4.57.6 + torch 2.6.0（CPU 即可），加载小型本地嵌入模型（首选 `sentence-transformers/all-MiniLM-L6-v2`，~90MB；备选 bge-small。下载经 hf-mirror 镜像或预置缓存，模型权重与缓存不入库）。

**改造点**：
- `RelevanceScorer` 接口化：词法（现有）与语义（嵌入余弦）双实现，运行时可切换/并存；
- 语义相关性用于：子问题-文档打分、近重复文档的语义合并（词法去重之外的补充）、按子问题的证据分组视图；
- "融合"边界（如实）：P1 做排序 + 去冗余 + 分组整理，**不做**生成式摘要或主张级融合；
- 双轨评价：trace 同时记录词法代理 score 与语义 score，同一任务对比停止点与证据质量——这本身是本轮的核心研究产出；
- 可复现：嵌入结果落盘缓存，离线回放语义轨同样 0 网络依赖。

**验收标准（建议）**：示例任务上双轨对比报告（停止轮数、证据命中、误判对比）+ 全部离线测试通过 + 回放一致性保持。

## P1-b：三层 Memory 渐进式实现

- `WorkingMemory`：当前任务内证据滑动窗口 + 最近决策上下文（进程内对象，接口先固定）；
- `EpisodicMemory`：本地 JSONL 轨迹库（直接复用现有 trace 格式），按任务名/子问题检索的最小接口；
- `LongTermMemory`：JSON KV 文件存策略参数与任务统计，只做存取接口，**不做**学习算法；
- 元元认知接口预留：Evaluator 可插拔注册；trace 增加评价器自报置信度字段（为后续"评价器校准"研究留口，本版本不实现校准本身）。

## P1-c：评测集扩展（支撑以上对比）

- 扩至 10+ 任务，含故意不可满足任务（真实触发 diminishing / forced 停止路径）；
- 自动评分脚本：停止决策正确率、轮数效率、证据命中率；
- 词法 vs 语义评价器在同一评测集上量化对比。

## 环境与风险（如实）

| 风险 | 应对 |
|---|---|
| torch 为 CPU 版，嵌入吞吐低 | 演示任务规模小（每任务 <50 文档）可接受；不动 torch/CUDA，确需 GPU 时另行评估并记录 |
| HF 模型下载可达性（本机网络对部分境外站点间歇不稳） | hf-mirror 镜像 / 预下载缓存；失败则提交阻塞报告 |
| 检索后端不稳（已验证） | 沿用重试/降级/缓存机制 |

## 交付节奏

P1-a 真实运行双轨对比跑通 → 中期交付（GPT 评审）；P1-b/c 完成 → 按 HANDOFF 节点 C 风格交付。每阶段独立分支 + PR + 离线测试全绿。
