## 一、实验目标与案例集

**研究问题**（任务书第二节）：词法评价器在什么情况下错误判断证据状态？引入现成语义相关性模型后，能否减少这些错误并使停止建议更合理？重点在评价质量对元认知调控的影响，不在嵌入模型本身。

**案例集**（`experiments/p1a/cases.json`，20 案例 + 5 快照）：
- **15 条真实检索证据**：取自 kv_cache_llm 任务的演示轨迹（`artifacts/demo`），原始文本经 URL 反查本地搜索缓存恢复，来源/URL/轮次/策略全部保留；
- **5 条构造对抗案例**：同义改写（B/H）、主题词重叠（C）、行话表述（E）、覆盖主题缺关键条件（CALC），构造意图在 `intent` 字段声明；
- **两层候选标注**：文档层相关性（每文档 × 3 子问题，附标注依据）+ 子任务层充分性（5 个固定证据快照：S1 同质冗余 / S2 伪相关覆盖 / S3 真实运行第 2 轮状态 / S5 缺关键条件 / S6 真实最终状态）；
- **标注状态：CANDIDATE**——由 GLM 起草，未经 GPT/研究人员核查，**不构成人工金标准**；结论均以此为前提。

## 二、词法基线的具体错误（第一交付节点，`results/report_node1.md`）

60 标注对中错 18（FN 7 / FP 11），离线复现（`python experiments/p1a/run_baseline.py`）：

1. **系统性跨子问题误归属（真实数据新发现）**：7 条真实证据（e008–e014）被误判为 definition 相关——definition 子问题词表最宽，任何提及 KV cache/attention/inference 的文档都能通过相对边际规则归给它；其中 e011/e012（技术综述）同时漏判 techniques，一因双错；
2. **同义改写/行话漏检**：真实 e014（"compression" 表述，词法分 0.149 差阈值 0.001）+ 构造 B/E/H 复现（0.02–0.13）；
3. **主题词重叠伪相关**：构造 C（游戏显卡 VRAM 页）被判 cost 相关（0.231）；
4. **错误停止建议（快照 S2）**：伪相关把 cost 覆盖推过 K=2，评价器输出 sufficient/stop，候选标注为 cost 关键信息不足——词法误判直接传导为元认知层错误停止；
5. **覆盖计数无法区分冗余（S1）**：5 篇同质入门文、同一论文 html/pdf 双版本均计入覆盖。

## 三、语义评价的改善与退化（第二交付节点，`results/report.md`）

同案例集、同接受规则形状（绝对阈值 + 0.6 相对边际）、同生产快照评价器；all-MiniLM-L6-v2（本地缓存，零新增依赖）；阈值 0.4/0.5/0.6 均为探索性。

**改善（修正 5/18）**：e011/e012→techniques 归因纠正、e014 同义漏检纠正、e010→definition 误归属纠正、C 主题重叠伪相关纠正。

**退化（新引入 16）**：主要是主题性伪接受——e001/e004（入门文）被误判 techniques 相关（0.53–0.57）、e008/e009/e013→techniques、e002/e011/e012/e013/e015→cost 等；另有 e006→definition 真相关被拒（0.4999 差 0.0001）。免阈值分离度为负（min 正对 0.39 < max 负对 0.72）。

## 四、仅靠语义相关性无法解决的充分性问题（Q5）

1. **冗余≠覆盖**：同质文档相似度同样高，成对相似度表达不了集合的边际信息量（S1 在语义臂下同样覆盖虚高）；
2. **主题相似≠回答条件满足**：用量计算器（CALC）与 cost 子问题主题高度相似（相似度 0.6+），但"为何增长"的机制信息缺失，语义臂无法检验集合是否包含关键回答条件（S5 在 0.4/0.5 下被误判可停止）；
3. **相似度不构成充分性证明**：按任务规范，任何基于相似度或更高 score 的充分性宣称不成立；充分性仍需结构性证据（覆盖、多样性、关键条件）。

## 六、已知局限（如实）

1. 案例集小（20 例）且标注为候选（GLM 起草），个别标注属边界判断（如 e003→cost 的"memory math"是否构成回答条件）；
2. 语义臂只用子问题文本（未用关键词表）与小型通用模型，未做领域微调或检索增强式嵌入（如加指令前缀）；固定阈值为探索值；
3. 全部结论来自固定证据快照的静态比较，未验证动态检索闭环中的行为；
4. 案例任务单一（kv_cache_llm），跨任务稳定性未知。

## 七、下一轮建议（任务书第九节要求列出）

1. 先由 GPT/研究人员核查候选标注（尤其 7 处 definition 误归属与 e003/cost 边界项），确认研究问题成立后再投入工程化；
2. 若核查通过，语义融合的工程化方向应以"归因纠正 + 主题伪接受抑制"的组合信号为目标（词法命中或语义高相似同时满足才接受），而非单独替换为相似度阈值——本实验数据支持该组合的必要性；
3. 充分性层需要成对相关性之外的结构性判据（关键回答条件清单、集合内冗余度量），这是词法与语义都缺的能力，建议作为独立研究点。

以上建议基于本实验数据，是否采纳及后续动态检索实验由 GPT 决定。
